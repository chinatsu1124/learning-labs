01 / mental model

先理解 wrangler 到底在做什么

Wrangler 是 Cloudflare 官方的命令行工具，专门用来开发、调试和部署 Workers（边缘函数）和 Pages（静态站点 + 函数）。它把「写代码 → 本地预览 → 上传到 Cloudflare → 绑定资源」整条链路收进一个 CLI。

wrangler 管的几样东西
Worker
一段跑在边缘的 JS/TS 代码。每个 Worker 是一个项目，有自己的入口文件和配置。
wrangler.toml
项目配置文件。声明名字、入口、兼容日期、环境变量和各种资源绑定。也支持 wrangler.jsonc。
binding
把外部资源接进代码。KV、R2、D1、队列、密钥等，在配置里声明后，运行时通过 env 访问。
account
你的 Cloudflare 账号。wrangler login 授权后，部署的资源都归在这个账号下。
名字由来

「Wrangler」是「牧马人 / 牲口管理员」的意思 —— 帮你把一群分散在边缘节点上的 Worker 管起来。它不是框架，是部署工具链。

02 / install

两种装法：全局 还是 跟着项目走

Wrangler 是个 npm 包，需要先有 Node.js（建议 18 以上）。推荐按项目安装，团队里每个人用的版本就被锁进 package.json，不会因为全局版本不同而踩坑。

# 在项目目录里作为开发依赖安装 npm install -D wrangler@latest # 之后所有命令都用 npx 触发，版本跟着项目走 npx wrangler --version npx wrangler deploy
# 装到全局，任何目录都能直接 wrangler ... npm install -g wrangler # 验证 wrangler --version # ⛅️ wrangler 4.x.x
# 一条命令拉起完整项目（含 wrangler、示例代码、配置） npm create cloudflare@latest my-worker # 按提示选模板（Hello World / 框架 / Pages…），自动装好 wrangler cd my-worker
不想记 npx

按项目安装后，把命令写进 package.json 的 scripts："deploy": "wrangler deploy"，然后 npm run deploy 即可。也可以用 pnpm / yarn / bun 代替 npm。

03 / login

先把 CLI 和你的账号连起来

部署前必须授权。wrangler login 会打开浏览器走 OAuth，授权后凭证存在本地，后续命令自动带上。

~/my-worker — wrangler

$ npx wrangler whoami
Account Name Account ID
my-account a1b2c3d4e5f6...
login

浏览器授权

  • wrangler login 打开浏览器登录
  • 本地开发机、个人电脑首选
token

API Token

  • CI / 无浏览器环境用环境变量
  • CLOUDFLARE_API_TOKEN=xxx
check

确认身份

  • wrangler whoami 看当前账号
  • wrangler logout 退出
CI 里不要 login

GitHub Actions 等自动化环境弹不出浏览器。去 Cloudflare 控制台建一个 API Token，作为 secret 注入环境变量 CLOUDFLARE_API_TOKEN（必要时再加 CLOUDFLARE_ACCOUNT_ID），wrangler 会自动读取。

04 / first worker

四步跑通 本地开发到上线

一个 Worker 的最小闭环就这四步：写代码、本地预览、部署、看线上。先把流程跑顺，配置和绑定后面再加。

1写 src/index.ts
2wrangler dev
3wrangler deploy
4wrangler tail
5改完重复
最小 Worker 代码
// src/index.ts —— 一个 Worker 就是一个导出的 fetch 处理器 export default { async fetch(request, env, ctx) { return new Response("Hello from the edge 👋"); }, };
~/my-worker — dev & deploy
$ npx wrangler dev

# 改代码自动热重载，按 b 在浏览器打开，按 x 退出

$ npx wrangler deploy

Deployed my-worker
https://my-worker.my-account.workers.dev
dev

本地预览

  • wrangler dev 默认本地模拟运行
  • 加 --remote 在真实边缘上跑
deploy

部署上线

  • wrangler deploy 上传并发布
  • 得到 *.workers.dev 地址
delete

下线

  • wrangler delete 删除这个 Worker
  • 误部署时清理用
deploy ≠ publish

老教程里的 wrangler publish 已经改名为 wrangler deploy。如果你看到 publish 报错或提示废弃，换成 deploy 即可。

05 / config

一份够用的 wrangler.toml

配置文件是整个项目的中枢。最关键的三项是 name（Worker 名字）、main（入口文件）和 compatibility_date（运行时行为锁定在某一天，避免平台升级悄悄改变行为）。

# wrangler.toml name = "my-worker" main = "src/index.ts" compatibility_date = "2026-01-01" # 明文变量，运行时 env.API_BASE 可读 [vars] API_BASE = "https://api.example.com" # 绑定一个 KV 命名空间，代码里用 env.CACHE [[kv_namespaces]] binding = "CACHE" id = "a1b2c3d4..." # 自定义域名路由（可选） [[routes]] pattern = "api.example.com/*" zone_name = "example.com"
多环境

用 [env.staging] / [env.production] 区分环境，部署时 wrangler deploy --env staging。每个环境可以有不同的变量、绑定和路由。

compatibility_date 别乱填未来

它代表「用这一天的运行时语义」。把它设成项目真实开始的日期，平台之后的破坏性变更就不会自动套到你头上。需要新特性时再手动往后调并测试。

06 / bindings & secrets

给 Worker 接上数据和密钥

Worker 本身只有计算，要存数据、读密钥得靠绑定。绑定在配置里声明，代码里通过 env 拿到；密钥则不写进配置，单独用命令加密上传。

vars

明文变量

  • 写在 [vars] 里
  • 非敏感的配置项，如域名、开关
secret

加密密钥

  • wrangler secret put API_KEY
  • 不进 git，加密存在云端
KV

键值存储

  • wrangler kv namespace create CACHE
  • 低延迟读、最终一致
D1 / R2

数据库与对象

  • D1 是 SQLite 数据库
  • R2 是 S3 兼容对象存储
~/my-worker — secrets & kv
$ npx wrangler secret put API_KEY
? Enter a secret value: ********
Success! Uploaded secret API_KEY

$ npx wrangler kv namespace create CACHE
Add the following to your wrangler.toml:
[[kv_namespaces]]
binding = "CACHE"
id = "0f2ac74b..."
// 代码里统一从 env 读，绑定名就是 env 上的字段 export default { async fetch(request, env) { const token = env.API_KEY; // 来自 secret const hit = await env.CACHE.get("k"); // 来自 KV 绑定 return new Response(hit ?? "miss"); }, };
密钥不要写进 wrangler.toml

[vars] 里的内容会进版本库，等于明文公开。任何 token、密码、API key 一律走 wrangler secret put。本地开发要用时，放进不提交的 .dev.vars 文件。

07 / logs & rollback

上线之后 怎么看怎么回滚

部署不是终点。线上报错要能实时看日志，发版出问题要能一键回滚到上一个好版本。

wrangler tail实时串流线上请求日志，定位报错
wrangler deployments list查看历史部署版本
wrangler rollback回滚到上一个版本
wrangler versions upload上传新版本但先不放量
wrangler dev --remote在真实边缘环境调试
wrangler pages deploy ./dist部署静态站点到 Pages
~/my-worker — wrangler tail
$ npx wrangler tail
Connected to my-worker, waiting for logs...

(log) cache miss for key=home
GET https://my-worker.workers.dev/x Error @ 12:04:33
(error) TypeError: env.DB is undefined
Pages 也归 wrangler 管

静态站点（含本仓库）可以用 wrangler pages deploy ./dist --project-name=site 部署，或者直接连 Git 仓库让 Cloudflare 自动构建。两条路都行，CLI 适合手动发布和 CI。
