01 / mental model

先理解 gh 和 git 不是一回事

git 管的是本地的版本历史（commit、branch、merge），它不知道 GitHub 的存在。gh 是 GitHub 官方 CLI，管的是 GitHub 平台上的协作对象 —— Pull Request、Issue、Actions、Release。两者配合：git 提交代码，gh 走流程。

gh 管的协作对象
repo
仓库。创建、克隆、fork、查看，不用打开网页。
pr
Pull Request。从当前分支建 PR、看评审、查 CI、合并，全在终端。
issue
问题与任务。建、列、查、评论、关闭。
run
Actions 工作流。看流水线状态、追日志、重跑。
api
万能出口。CLI 没封装的功能，用 gh api 直接打 REST / GraphQL。
一句话区分

git push 把 commit 推上去；gh pr create 才是发起一次评审请求。提交是 git 的事，协作流程是 gh 的事。

02 / install

挑你系统的 包管理器装上

gh 是个独立二进制，各平台都有官方包。装完用 gh --version 验证。

# Homebrew（最常用） brew install gh # 或 MacPorts sudo port install gh gh --version # gh version 2.x.x
# winget（Windows 自带） winget install --id GitHub.cli # 或 Scoop / Chocolatey scoop install gh choco install gh
# Debian / Ubuntu —— 加官方源后 apt 安装 sudo apt update && sudo apt install gh # Fedora / RHEL sudo dnf install gh # Arch sudo pacman -S github-cli
apt 装不到？

部分发行版自带的源里 gh 版本很旧，甚至没有。按 官方 Linux 安装文档 先加 GitHub 的 apt 源（导入 keyring）再 install，能拿到最新版。

03 / auth

第一步永远是 gh auth login

装完先授权，否则任何操作都会提示未登录。gh auth login 是交互式问答：选 GitHub.com 还是企业版、用 HTTPS 还是 SSH、浏览器登录还是粘 token。新手一路回车走浏览器最省事。

~ — gh auth login
$ gh auth login
? What account do you want to log into? GitHub.com
? What is your preferred protocol for Git operations? HTTPS
? How would you like to authenticate? Login with a web browser
! First copy your one-time code: ABCD-1234
- Press Enter to open github.com in your browser...
✓ Authentication complete.
✓ Logged in as your-username
login

登录

  • gh auth login 交互式授权
  • 顺手让它管 git 凭证
status

查状态

  • gh auth status 看登录了哪个账号
  • gh auth token 打印当前 token
switch

多账号

  • gh auth switch 切换账号
  • gh auth logout 退出
顺手解决 git 推送鉴权

登录时选「让 gh 管理 git 凭证」，之后 git push 也不再要你输密码 —— gh 把 HTTPS 凭证一起配好了。CI 环境则用 GH_TOKEN 环境变量代替交互登录。

04 / repo

仓库的 建、克隆、看

常见仓库操作不用再打开网页。注意 gh 用 owner/repo 这种简写就能定位仓库，比贴完整 URL 快。

gh repo create交互式新建仓库（可同时推本地代码）
gh repo clone owner/repo克隆仓库，无需完整 URL
gh repo forkfork 并自动配置 upstream
gh repo view --web在浏览器打开当前仓库
gh repo list owner列出某用户/组织的仓库
gh browse把当前文件/行号在网页打开
gh repo view 当帮助文档用

在一个陌生仓库里 gh repo view 直接在终端渲染 README，比切浏览器快。加 --web 才是打开网页。

05 / pull request

核心场景：一条分支到合并

gh 最高频的用途就是 PR。典型流程：本地建分支、提交、推送、建 PR、等评审和 CI、合并。中间不用碰一次浏览器。

1git push
2gh pr create
3gh pr checks
4review
5gh pr merge
~/project — pr flow
$ git switch -c fix/login
# ...改代码、commit...
$ git push -u origin fix/login
$ gh pr create --fill
Creating pull request for fix/login into main
✓ https://github.com/you/project/pull/42
$ gh pr checks
✓ build 1m20s
✓ test 2m05s
$ gh pr merge --squash --delete-branch
✓ Squashed and merged pull request #42
create

发起 PR

  • gh pr create --fill 用 commit 自动填标题正文
  • --draft 建草稿 PR
inspect

查看

  • gh pr list 列出 PR
  • gh pr view 42 --web 网页打开
  • gh pr diff 看改动
review

评审与试跑

  • gh pr checkout 42 拉别人的 PR 到本地
  • gh pr review --approve 批准
merge

合并

  • --squash / --merge / --rebase 选策略
  • --delete-branch 合完删分支
checkout 别人的 PR 来 review

gh pr checkout 42 会把这个 PR 的分支拉到本地，让你跑起来、改一改再推回去。这是本地评审最实用的一招，纯网页做不到。

06 / issue

Issue 也是 一行命令的事

提 bug、记 TODO、查任务，不用切回网页打断思路。和 PR 一套语法风格，记一个就会另一个。

gh issue create交互式新建 issue
gh issue list --assignee @me列出分配给我的
gh issue view 17终端里看 issue 详情和评论
gh issue comment 17 -b "..."评论
gh issue close 17关闭
gh issue status看和我相关的 issue 概览
07 / actions & release

盯流水线、发版本

推完代码想知道 CI 过没过，不用刷网页 —— gh run 直接在终端看 Actions。发布版本也能一条命令搞定。

gh run list最近的工作流运行
gh run watch实时盯一次运行直到结束
gh run view --log-failed只看失败 step 的日志
gh run rerun重跑（可只重跑失败的 job）
gh release create v1.0.0建一个 release
gh release create v1.0.0 ./dist/*顺带上传产物附件
~/project — gh run
$ gh run list --limit 3
✓ CI push main fix/login 1m20s
X CI push main add-cache 0m48s
✓ CI pull main docs 1m02s
$ gh run view --log-failed
test › should cache responses
AssertionError: expected 200 got 500
CI 红了先看这个

gh run view --log-failed 直接跳到失败 step 的日志，不用在网页里一层层点开 job。配合 gh pr checks 看 PR 的整体状态。

08 / api & extensions

进阶：api、别名、扩展

CLI 封装的命令覆盖日常 80%。剩下的边角功能用 gh api 直接打接口；高频命令设别名；想要更多功能装扩展。

# gh api —— 直接调 REST，自动带鉴权和分页 gh api repos/cli/cli/releases/latest --jq '.tag_name' # 也能打 GraphQL gh api graphql -f query='{ viewer { login } }' # 别名：把常用长命令缩短 gh alias set prc 'pr create --fill' gh prc # 等于 gh pr create --fill # 扩展：社区命令，一行安装 gh extension install dlvhdr/gh-dash # PR/issue 仪表盘 TUI
gh api 是后备万能钥匙

遇到 gh 没有专门子命令的操作（改仓库设置、查冷门字段……），先想 gh api。它复用你的登录态，省去手搓 curl + token 的麻烦。
