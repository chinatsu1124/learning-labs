01 / TWO PHILOSOPHIES

先说清楚：它们到底是什么？

CPU（中央处理器）是电脑的「大脑」：少量（4～16 个）非常强的核心，主频高、缓存大、控制逻辑极其复杂，什么任务都能接，尤其擅长逻辑分支多、步骤之间环环相扣的串行任务。GPU（图形处理器）最初是为渲染画面而生：屏幕上几百万个像素要做几乎一样的计算，于是它选择了完全相反的路——把成千上万个简单核心铺满芯片，单个核心很弱，但一起上就是洪流。

side by side · 同一块硅片，两种花法
🧠

CPU · 全能指挥官

少而强 · 低延迟优先
  • 核心：4～16 个「重型」核心，每个都会乱序执行、分支预测
  • 主频：3～5 GHz，单核速度拉满
  • 缓存：几十 MB 三级缓存，把常用数据贴身放
  • 擅长：操作系统、业务逻辑、数据库——分支多、依赖强、要求快速响应的活
🌊

GPU · 人海战术

多而简 · 高吞吐优先
  • 核心：数千到上万个「轻型」核心，32 个一组锁步执行同一条指令
  • 主频：1～2 GHz，单核比 CPU 慢得多
  • 显存：GDDR / HBM，带宽是普通内存的几十倍
  • 擅长：图形渲染、矩阵运算、深度学习——海量数据做同一种计算的活
一句话记住它

CPU 像 4 位数学教授，GPU 像 5000 名小学生。一道高难度微积分，教授完胜；5000 道两位数加法，小学生军团碾压。区别不在谁更强，而在任务长什么样。

常见误解

GPU 不是「更高级的 CPU」，也替代不了 CPU。你的电脑里两者一直在协作：CPU 跑操作系统、调度一切，遇到大规模并行计算才把活「外包」给 GPU——GPU 是 CPU 指挥下的加速器，自己一个人开不了机。

02 / SILICON BUDGET

看图说话：晶体管都花在哪了？

芯片设计的本质是分配预算——硅片面积就这么大，每平方毫米给谁？CPU 把大头给了控制电路（乱序执行、分支预测）和缓存，真正做计算的 ALU 只占一小块；GPU 反过来，控制和缓存压到最薄，把面积铺满运算单元。

CPU 为什么"浪费"这么多面积？

因为它的使命是把单个线程的延迟压到极限。分支预测猜对率 95%+、乱序执行填满流水线空隙、大缓存把内存访问从几百周期降到几个周期——这些都不直接做计算，但能让那一个线程快得飞起。

GPU 核心为什么能做到几千个？

靠「拼单」：32 个线程编成一个 warp，共享同一套取指、译码电路——控制成本摊到每个线程头上只剩 1/32。省下来的面积全部换成 ALU。代价是：32 个线程必须走同一条指令，队形不能乱（后面会看到乱了会怎样）。

并行任务：GPU 一拍洪流

1,152 个像素 ÷ 6 核 = CPU 要排 192 轮；GPU 一人领一个像素，一波就完——就算它的时钟慢 4 倍，吞吐还是甩开 CPU 几十倍。数据量越大，差距越夸张：真实 GPU 跑图形和矩阵运算，比 CPU 快 10～100 倍是常态。

串行任务：1,151 个核心围观

每一步都要等上一步的结果，同一时刻只有一个核心有活干——GPU 的人海优势完全归零，只剩「单核比 CPU 慢几倍」这个劣势。这就是阿姆达尔定律的画面版：串行部分决定加速上限。

还有一个隐形减速带：分支发散

GPU 的 32 线程 warp 锁步走同一条指令。代码里来个 if/else，一半线程要走 A、一半要走 B 怎么办？答案很笨：整个 warp 把两条路都走一遍，走 A 时 B 组干瞪眼，走 B 时 A 组干瞪眼——这叫分支发散。所以分支密集的代码（业务逻辑、解析器）天生不适合 GPU。

04 / LATENCY VS THROUGHPUT

设计哲学：跑车，还是重载火车？

两颗芯片面对同一个敌人——内存太慢（一次内存访问要几百个时钟周期，够 ALU 算几百次）。但它们的应对完全相反：CPU 选择把延迟降下来（大缓存 + 预测 + 预取），GPU 选择把延迟藏起来（线程多到永远有人有活干）。这是「跑车 vs 重载火车」：跑车 2 个座位但极快——延迟低；火车 1000 个座位但启动慢——吞吐大。

timeline · 同样遇到「读内存要等 400 拍」，两种应对
为什么游戏逻辑、网页响应离不开 CPU

用户点了一下按钮，要的是这一次操作立刻有反馈——这是延迟问题，跑车的主场。哪怕 GPU 吞吐再大，让它处理单次点击，就像为了送一个包裹发一整列火车。

为什么 AI 训练、视频渲染离不开 GPU

训练时没人在乎「单个像素何时算完」，在乎的是每秒总共能算多少——这是吞吐问题，火车的主场。单个线程慢一点完全无所谓，反正几万个线程一起在跑。

05 / THE DATA TOLL

隐藏成本：数据过桥要交税

GPU 再快，有个绕不开的麻烦：它只能直接访问自己的显存。数据住在内存（CPU 这边），想让 GPU 算，得先过 PCIe 这座「桥」搬到显存，算完再搬回来。桥上的车速比两岸慢几十倍——很多时候，搬运比计算本身还贵。走一遍完整流程👇

结论：小任务别过桥

排序 1,000 个数、算一次哈希——这种活交给 GPU，光搬运和启动的固定开销就远超计算本身，CPU 早就当场算完了。GPU 划算的条件：① 数据量足够大；② 或者数据能留在显存里反复使用。

深度学习恰好两条全占

训练开始时把模型权重搬进显存，之后成千上万轮迭代全在显存里进行，过桥只发生在喂数据时——固定成本被摊薄到忽略不计。这（加上矩阵乘法本身极度并行）就是 AI 长在 GPU 上的根本原因。顺带一提：大模型时代天天听到的「显存不够」，就是模型权重塞不进 VRAM 的意思。

延伸：苹果 M 系列的「不过桥」方案

Apple Silicon 把 CPU 和 GPU 做进同一颗芯片、共用同一块统一内存（Unified Memory）——数据不用搬，两边直接访问同一份。代价是内存焊死不能扩展、带宽上限不如顶级独显的 HBM，但「零搬运」让它跑中小模型格外舒服。
